# Cruz, Vanneschi, Painho & Rita (2022)

**Title:** "Automatic Identification of Addresses: A Systematic Literature Review"
**Venue:** ISPRS Int. J. Geo-Inf. 11(1):11 (29 Dec 2021) · https://doi.org/10.3390/ijgi11010011
**PDF:** `papers/survey_cruz-etal-2022_address-identification-review.pdf`

## Review notes (Claude, 2026-11-13)
- **Method:** PRISMA; Scopus + Web of Science, searched Apr + Dec 2021; 122 → 41 papers (2002–2021); only Q1/Q2 journals and A-ranked conferences (so no arXiv). Mostly bibliometric (keyword / co-author networks); the detailed method review is §3.2.1 (~5 pages).
- **Taxonomy (§3.2.1, taken from Lin et al. 2020):** string-similarity methods · address-element methods (parse, then compare; HMM → CRF, libpostal) · deep learning (BiLSTM/GRU, attention, ESIM, BERT, GCN). Plus three kinds of similarity: string, semantic, spatial (§1).
- **Findings:** shift from HMM/CRF to semantic DL with attention after 2017; 46% of papers by Chinese authors; very recent hybrids add spatial constraints.
- **Gaps they list (§3.2.2):** representative, large datasets; duplicate place names; hierarchy-weighted address elements; fusing coordinates with text; systematic hyperparameter tuning; less human labelling; privacy (residential addresses as quasi-identifiers); no genetic programming yet.
- **Not in the review:** any shared / public benchmark; any per-error-type or hard-negative evaluation; siamese bi-encoders; transformer comparisons beyond two BERT papers. Each DL paper reports one headline F1/accuracy on its own data.
- **Our steps in its taxonomy:** 1 / 1b = string similarity (+ supervised combiner, like Santos et al. 2017 and Lee et al. 2020) · 2c libpostal = address-element · 3–5 = deep learning · ZIP blocking = a crude spatial constraint.

## Discussion takeaways (Claude, 2026-11-17)
Settled in discussion with David (main points in his own answers; corrections noted).

**Our steps in the review's taxonomy**

| Step | Family | Note |
|---|---|---|
| 1 / 1b string metrics → LR/RF/XGB | Boundary: string similarity applied to address elements | `features.py` splits number / street / ZIP first, then runs string metrics per element. The review files the same pattern (Comber & Arribas-Bel: CRF parse → per-element distances → classifier) under address-element. |
| 2c libpostal | Address-element | CRF parser + decision rule |
| 3 char BiLSTM siamese | Deep learning | The review has no siamese / bi-encoder paper |
| 4 ESIM + word2vec | Deep learning | Described in the review almost exactly as we built it (Lin et al. 2020) |
| 5a/5b DistilBERT bi-/cross-encoder | Deep learning | The review's two BERT papers predict coordinates (GSAM) or parse (BERT-CRF); neither classifies pairs |
| ZIP split | Evaluation protocol, not a method | Split = tests on unseen areas (generalisation). Not the same as blocking (comparing only nearby candidates), which is the crude spatial constraint. |

**§3.2.2 gaps vs our work**

| Listed gap | Ours? |
|---|---|
| Minimise human labelling of train/test data | Yes: labels come from the Overture ↔ Foursquare bridge files, no hand labelling (the bridge labels can be noisy) |
| Systematic comparison of architectures / hyperparameters [Santos et al.] | Architectures yes (five families, one protocol, same splits, seeds); hyperparameters only partly |
| Duplicate place names [Lin] | Related, not the same: theirs = identical names in different places, resolved from context outside the string; our case1 / case2s differ in one element and can be resolved from the text |
| Weight address elements by hierarchy [Lin] | We measure the failure it targets (case1 = house number under-weighted) but propose no weighting |
| Representative / large datasets | Not really; this gap is about size and coverage, not how hard the negatives are |
| Spatial fusion, privacy, genetic programming | No |

**Absences (not listed gaps, but our strongest claim):** the review names no shared benchmark, and each DL paper reports one headline F1 on its own data with negatives of unknown difficulty, so the scores can't be compared across papers (e.g. Lin 0.97 vs Chen's ABLC). No per-error-type or hard-negative evaluation either. Our case1 / case2s slices and the same-protocol comparison fill both.

**Corrections made:** "the review has no hybrids" (it does: hybrid string metrics, Comber's parse-then-compare, and the 2021 string + semantic + spatial POI papers); "representative datasets" as the gap closest to hard negatives (it is duplicate place names / element weighting); "covers BERT" is an absence in the review, not one of its listed gaps.
